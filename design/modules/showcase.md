It explains **what / trigger / place** for shared controls and destinations, twenty marker pairs, four numbered wording priorities, editable grid notes, the actual M3 workbench, flowing conversation and the actual completion reveal. Ordinary content uses fine ruled rows, not a card gallery.
- `hero-transition.js/css`: one stable concept surface from the first symbol to the final wordmark and tagline. There is no moving/scaling brand-title handoff or second text layer. The static `[data-hero-home]` contains the wordmark and tagline and stays hidden after the runtime mounts; it is available when scripting is absent.
- `concept-motion.js`: four short currency/protection/policy symbols followed by the orange POLICY LENS wordmark and 「你的保單，付款前看清。」 in one parent layer, about 4.1 seconds in total. Sixteen complete insurer names fade in behind the symbols and retire before the final group settles. The generated DOM has a symbol wrapper/SVG/path and one title wrapper containing a wordmark/tagline group, plus a background wrapper with at most sixteen complete name spans. Only the active layer animates opacity and a small 2D translation through Web Animations; the runtime does not scan per-character DOM, write inherited style variables every frame, or use blur filters. Background insurer names use one text node per full name and finite Web Animations; per-character scans, dotted brand lettering and the second title animation remain removed.
- `concept-data.js`: the shared tagline is 「你的保單，付款前看清。」. The static market-source list may still use the insurer metadata independently of the animation.
- `showcase-chat.js`: a small local state adapter over the unchanged `PolicyAgentMotion` and `PolicyAgentReplies`, not a copy of the six-step app closure. Draft, transcript, mode, source context, busy token and pending reply are local. Close/hide settles pending content and cancels old motion; reopen preserves draft/transcript. Long response positioning remains owned by `PolicyAgentMotion`. Evidence uses `PolicyDemo.sources[].text`.
- `index.html`, `completion-preview.html`, `concept-preview.html`: load M1 theme/markers/notebook and M2 shared controls, including dynamic buttons. The prototype remains an independent reference entry.
- `scripts/build-preview.mjs`: embeds each entry's local styles, scripts, HTML images, CSS URL assets, and static asset literals in **all** scripts. It no longer special-cases only `app.js` for the paper SVG. Missing assets and external stylesheet/script dependencies fail the build. `scripts/serve.mjs` allowlists all module files and serves the showcase at `/`.
- `package.json`: includes syntax checks for the new page and module controllers. `README.md`: final-entry, offline, sample-boundary and integration documentation.
- Outputs: `dist/showcase.html` plus the three standalone reference entries. Build outputs are generated artifacts.

## Public APIs and DOM hooks

`window.PolicyHeroTransition.mount(host,{conceptOptions,onState})` returns `{play(),finish(),replay(),destroy(),state}`. States are `concept`, `ready`, `destroyed`; the former `handoff` state is no longer used. Concurrent `play()` reuses the current Promise. `finish()` cancels the current run and shows the final wordmark and tagline on the same surface. `replay()` finishes the previous run first. Reduced motion and forced colors show the complete wordmark and tagline immediately.

Hero hooks: `[data-hero]`, `[data-hero-concept]`, `[data-hero-home]`, `[data-hero-replay]`, `[data-hero-finish]`. The static home is a fallback, not a second animation target. No brand-name or paper-anchor hooks are required. Controller state/phase is exposed as `data-hero-state` / `data-hero-phase`.

`window.PolicyConceptMotion.mount(host,{name,tagline,insurers,autoplay,onPhase})` returns `{play(),pause(),resume(),finish(),destroy(),state,phase}`. It pauses its active animation while hidden or offscreen, preserves manual pause, and settles pending `play()` promises when finished or destroyed. Reduced-motion/forced-color changes finish immediately. The historical phase key `name` identifies the final brand/tagline group for caller compatibility; `data-concept-glyph` is `tagline`. The historical `scan` options no longer affect the simplified sequence.

`window.PolicyShowcaseChat.mount(host,{onQuestion})` returns `{open(),close(),replay(),submit(question),destroy(),busy,transcript,draft}`. `replay()` resets the local transcript and submits the flight-delay example. Enter submits, Shift+Enter adds a line, IME composition is preserved, Escape closes and returns focus to the opener. It deliberately uses the **Sunny Days Travel** chat sample and says so in its header/evidence; M3's three policy fixtures remain separate and are not falsely explained by the old reply library.

Chat hooks: `[data-showcase-chat]`, `[data-chat-panel]`, `[data-chat-open/close/replay/send]`, `[data-chat-feed/stack/evidence/status]`, `[data-agent-draft]`, `[data-chat-mode]`, `[data-chat-suggestion/source/save]`. Specific reply scenarios are retained for follow-ups; unmatched replies clear both scenario/source context and the previous evidence. On short screens the evidence desk yields to the composer; a source action presents exact wording inside the associated message through `.sc-chat-inline-source`. There is one chat adapter on this page. The existing motion library exposes only global `cancelAll()`, so this adapter is intended for the page's single active conversation; multiple independent simultaneous chat mounts would need a future scoped cancellation extension in the original library.

`window.PolicyShowcase` publishes `{hero,chat,workbench,generate(replay=false),destroy(),selectedPolicyId,selectedFindingIds}` for integration/acceptance. It owns the page's global listeners; `destroy()` removes them and destroys its mounted controllers. Non-persisted `pagehide` destroys the page; a persisted page stays usable after the browser restores it.

Policy integration: `[data-policy-workbench]` mounts the actual `PolicyWorkbench` composite with `PolicyFixtures.items`. `onSelection(id)` updates `[data-wording-excerpt]` using exact literal fixture quotes and resets `[data-checklist-options]`. All user/data text is escaped. Each four-priority mark carries `data-priority` and stable finding ID. Twenty visible swatches use M1's existing `.pl-marker[data-marker="1".."20"]`; M4 has no duplicate RGB palette.

Checklist hooks: native `[data-checklist-choice]` checkboxes, generate/replay/cancel buttons, `[data-checklist-result]`, `[data-showcase-reveal]`, `[data-reveal-content]`, `[data-reveal-row]`. Generation snapshots only selected findings from the current policy, including their questions/priorities/source labels. Replay uses that snapshot. Policy/checkbox changes cancel any reveal and invalidate the old snapshot. Cancel hides partial output while preserving choices. Hidden-document reveal cancellation leaves the completed, readable questions available. No export, sharing or reviewed status is invented.
