## Public APIs and DOM hooks

`window.PolicyHeroTransition.mount(host,{conceptOptions,onState})` returns `{play(),finish(),replay(),destroy(),state}`. States are `concept`, `handoff`, `ready`, `destroyed`. Concurrent `play()` reuses the current Promise. `finish()` invalidates the old run and lands immediately on the final policy home. `replay()` clears old concept/handoff work first. Reduced motion presents final home immediately. Resize or document hiding during the short handoff settles to home; ConceptMotion itself pauses/resumes the longer sequence when hidden or offscreen. Removing the host destroys its controller.

Hero hooks: `[data-hero]`, `[data-hero-concept]`, `[data-hero-home]`, `[data-hero-name]`, `[data-hero-copy]`, `[data-hero-paper]`, `[data-hero-replay]`, `[data-hero-finish]`. Controller state/phase is exposed as `data-hero-state` / `data-hero-phase`. The home becomes inert/ARIA-hidden during the concept and handoff; skip remains outside the inert stage content.

`window.PolicyShowcaseChat.mount(host,{onQuestion})` returns `{open(),close(),replay(),submit(question),destroy(),busy,transcript,draft}`. `replay()` resets the local transcript and submits the flight-delay example. Enter submits, Shift+Enter adds a line, IME composition is preserved, Escape closes and returns focus to the opener. It deliberately uses the **Sunny Days Travel** chat sample and says so in its header/evidence; M3's three policy fixtures remain separate and are not falsely explained by the old reply library.

Chat hooks: `[data-showcase-chat]`, `[data-chat-panel]`, `[data-chat-open/close/replay/send]`, `[data-chat-feed/stack/evidence/status]`, `[data-agent-draft]`, `[data-chat-mode]`, `[data-chat-suggestion/source/save]`. Specific reply scenarios are retained for follow-ups; unmatched replies clear both scenario/source context and the previous evidence. On short screens the evidence desk yields to the composer; a source action presents exact wording inside the associated message through `.sc-chat-inline-source`. There is one chat adapter on this page. The existing motion library exposes only global `cancelAll()`, so this adapter is intended for the page's single active conversation; multiple independent simultaneous chat mounts would need a future scoped cancellation extension in the original library.

`window.PolicyShowcase` publishes `{hero,chat,workbench,generate(replay=false),destroy(),selectedPolicyId,selectedFindingIds}` for integration/acceptance. It owns the page's global listeners; `destroy()` removes them and destroys its mounted controllers. Non-persisted `pagehide` destroys the page; a persisted page stays usable after the browser restores it.

Policy integration: `[data-policy-workbench]` mounts the actual `PolicyWorkbench` composite with `PolicyFixtures.items`. `onSelection(id)` updates `[data-wording-excerpt]` using exact literal fixture quotes and resets `[data-checklist-options]`. All user/data text is escaped. Each four-priority mark carries `data-priority` and stable finding ID. Twenty visible swatches use M1's existing `.pl-marker[data-marker="1".."20"]`; M4 has no duplicate RGB palette.

Checklist hooks: native `[data-checklist-choice]` checkboxes, generate/replay/cancel buttons, `[data-checklist-result]`, `[data-showcase-reveal]`, `[data-reveal-content]`, `[data-reveal-row]`. Generation snapshots only selected findings from the current policy, including their questions/priorities/source labels. Replay uses that snapshot. Policy/checkbox changes cancel any reveal and invalidate the old snapshot. Cancel hides partial output while preserving choices. Hidden-document reveal cancellation leaves the completed, readable questions available. No export, sharing or reviewed status is invented.
