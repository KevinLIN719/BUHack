    01

    A shared touch

    輕柔按下，清楚選擇。

    輕量平面按鈕，統一以由左至右的淡色填充回應操作。

    效果
    滑過、聚焦或選取時，底色由左向右填入。
    觸發方式
    按下按鈕，或選取目的地。
    適用位置
    主要操作、分頁、小工具及選擇項。

    你準備去哪裏？

    每次選一個目的地，動畫結束後仍能清楚看見選取狀態。

    把常用操作放在手邊。

    目的地：日本

    前端接入 · 按鈕與選項

    所有操作使用相同的平面細線與由左至右填充，不設立體陰影或彈跳。選項保留明確選取狀態，文字、焦點與點擊範圍保持穩定。

    所需檔案。 先載入 ui-theme.css 及 liquid-controls.css，再載入 liquid-controls.js。程式會自動掛載一次，重複明確掛載亦不會建立多份實例。

    保留原生按鈕，並由介面管理選取狀態。主要操作加上 data-liquid-variant="primary"；一般按鈕預設為輕量樣式，只有互動時浮現淡淡表面。需要展示完整平面表面時使用 data-liquid-variant="surface"。核取方塊外層使用緊湊的 .sc-check-toggle。

    <button type="button" aria-pressed="false">日本</button>
<span class="sc-check-toggle" data-liquid-control data-liquid-choice>
  <input type="checkbox" />
</span>

const controls = PolicyButtonMotion.mount(document);
controls.update({ releaseMs: 460 });
// 卸載時： controls.destroy();

    隊友提供的資料。 介面負責 aria-pressed、checked 及 disabled。本示例是已記錄的原生適配；原始 PixelToggle 引擎未有提供。

    02

    Read with a hierarchy

    用標記，讀出輕重。

    四個編號優先級，協助留意原文；顏色輔助標籤，不取代文字。

    效果
    20 組文字與底色色對；閱讀區統一使用四個優先級。
    觸發方式
    選取示例保單，或閱讀保單詳情。
    適用位置
    原文條款、閱讀重點及待確認問題。
    1. 1 · 首要投保前先釐清會影響決定的限制。
    2. 2 · 重要核對門檻、條件及限額。
    3. 3 · 待確認留意證明文件及實際要求。
    4. 4 · 參考保留對話時有用的細節。

    已選的虛構條款

    完整 20 色參考

    參考色盤提供較多選擇；本示例一致使用四個編號優先級，顏色並不代表保障判定。

    前端接入 · 螢光優先級

    在支持閱讀重點的原文字句上加標記，並讓原文、解釋及最終問題保持同一優先級。

    所需檔案。 載入 ui-theme.css 及 ui-markers.css，無須 JavaScript。

    data-priority 1–4 對應首要至參考，分別使用櫻桃紅、琥珀、青綠及紫羅蘭。data-marker 1–20 選取參考色；色盤編號並不等於優先級。

    <mark class="pl-marker" data-priority="1">逐字原文</mark>
<span class="pl-priority" data-priority="1">1 · 首要</span>

<!-- 可選用完整參考色盤的其他顏色。 -->
<mark class="pl-marker" data-marker="12">補充筆記</mark>

    隊友提供的資料。 提供來源文字、逐字引文及閱讀優先級。加入標記時，請保留原文不變。

    03

    Room to think

    把想法寫在網格上。

    保留付款前要確認的細節；安靜的網格，讓每個問題都有位置。

    效果
    淡淡的網格，襯托可直接編輯的純文字筆記。
    觸發方式
    直接輸入，或從對話保留問題。
    適用位置
    閱讀筆記，以及帶去向保險顧問確認的清單。

    筆記只留在此頁，重新整理後會清空。

    前端接入 · 網格紙筆記

    適合用於要保留的筆記及問題。網格只放在閱讀或書寫區，讓其餘頁面保持簡潔。

    所需檔案。 載入 ui-theme.css 及 ui-notebook.css；.pl-grid-paper 繪製 24px 網格，無須 JavaScript。

    如要使用本頁的筆記樣式，請在 .sc-page 內加上 .sc-notepaper，並載入 showcase.css，以加入細線、邊線、間距及 24px 書寫節奏。

    <div class="sc-notepaper pl-grid-paper">
  <label for="note-example">投保前，我想問清楚……</label>
  <textarea id="note-example" rows="4"></textarea>
</div>

    隊友提供的資料。 隊友決定筆記的儲存方式；本示例只保留於目前頁面。

    04

    A document you can handle

    在不同保單之間切換。

    把一張保單拖到另一張上交換位置；開啟紙張，即可閱讀對應條款。

    效果
    三張可拖拽交換的保單，以及獨立的詳情揭示。
    觸發方式
    拖拽交換；按下紙張，或用鍵盤查看。
    適用位置
    選取及比較來源文件。

    下方三份保單均為虛構示例。紙張質感用於文件；問題和閱讀重點則保留上方的細線清單形式。

    保單書籤 · 按下揭示

    把一則筆記牽引到眼前。

    小書籤沿着所選保單描邊、輕拉，再把視線帶到閱讀筆記。內容保留 原文條款、四個閱讀優先級，以及需要確認的問題。

    瞄準 → 描邊 → 牽引 → 搬運 → 落位。按下下方任何保單，即可查看筆記揭示。

    前端接入 · 保單交換與詳情揭示

    適合處理多份不同保單。拖拽會交換位置；開啟紙張則使用獨立的書籤牽引效果，帶出對應原文。

    所需檔案。 依次載入 policy-fixtures.js → policy-deck.js → policy-pull.js → policy-workbench.js，並加入 policy-deck.css、policy-pull.css 及主題／標記樣式。

    workbenchHost 可以是已連接頁面的空 div。每個項目需有 id、title、kind、summary、sourceLabel、excerpt 及 findings；每個重點需有 id、priority、title、question，以及 excerpt 中逐字包含的 quote。

    const workbenchHost = document.querySelector('[data-policy-workbench]');
const desk = PolicyWorkbench.mount(workbenchHost, {
  items: PolicyFixtures.items,
  pullToken: 'bookmark',
  onSelection(id, item) { /* 同步自己的閱讀區 */ }
});
desk.inspect(PolicyFixtures.items[0].id);
// 卸載時： desk.destroy();

    隊友提供的資料。 提供文件記錄及閱讀重點。本示例採用原生 PolicyDeck 適配；原先 CardSwap 包裝器所需的 CardSwapEngine.js 及 motion-runtime 未有提供，因此這裏不聲稱與原引擎逐幀相同。

    前端接入 · 書籤筆記揭示

    用途與位置。 用保單書籤取代蜘蛛，以牽引線清楚連結文件與對應的詳情筆記。

    觸發方式。 按下保單紙張或「閱讀條款」；重播使用目前所選保單。減弱動態或取消時，筆記仍保持可讀。

    所需檔案。 組合示例使用 policy-pull.js/css、policy-workbench.js，以及上述保單與示例資料檔案。重用同一個 Workbench 實例，它已管理覆蓋層和筆記揭示。

    // 掛載上述工作台時加入此選項：
pullToken: 'bookmark'  // 亦可使用： 'shield' or 'policy'.

// 使用既有實例開啟或重播所選筆記。
desk.inspect(desk.selectedId);
// 卸載時： desk.destroy();

    建議用法。 條款提示可從原文標記連到解釋；未來的儲存操作可從問題連到筆記清單。本例實際展示的是保單到筆記的連結。

    隊友提供的資料。 提供所選保單 ID、逐字原文及閱讀重點／問題。這項保險場景適配使用參考既有點擊動畫後編寫的原生 PolicyPull 控制器。

    LOCAL WORDING COMPANION

    一次，看清一條。

    晴日旅遊 · 虛構示例 · 未接入 AI 服務

    解釋條款 · 用白話拆解條件、限制和所需證明。

    前端接入 · 流動對話

    適合放在不清楚的條款或待討論問題旁。訊息由輸入區升起，回覆再連同來源展開。

    所需檔案。 依次載入 demo-data.js → agent-replies.js → agent-motion.js → showcase-chat.js，並加入 agent.css、主題／標記樣式及本頁對話樣式。

    複製完整 [data-showcase-chat] 結構，包括輸入表單／草稿、訊息區、來源／狀態及控制項；此適配需要這些掛點，空 div 並不足夠。

    const chatHost = document.querySelector('[data-showcase-chat]');
const chat = PolicyShowcaseChat.mount(chatHost, {
  onQuestion(question) { /* 保留至自己的筆記 */ }
});
chat.submit('航班延誤條件怎樣寫？');
// 卸載時： chat.destroy();

    隊友提供的資料。 此適配使用本機示例回覆庫；服務準備好後，由隊友替換 showcase-chat.js 的回覆取得方式。目前動態模組支援一個使用中的對話。

    讓重要問題，一起浮現。

    由四種重點螢光色混成的炫彩光洗，帶出白色網格確認清單。每項問題可勾選，並可展開查看原文依據。

    效果
    炫彩光洗由上往下帶出筆記清單。
    觸發方式
    選取目前保單的問題，再按生成。
    適用位置
    已準備好的清單、閱讀摘要或完成內容。
    所選虛構保單的問題

    請至少選一個問題。

    前端接入 · 完成衝擊波

    結果準備好後，以櫻桃紅、琥珀、青綠與紫羅蘭重點色混成由上往下的光洗。白色網格紙上每項有原生 Checkbox；勾選只記錄這份清單的進度。重播或停止展示會保留勾選，重新生成才建立新清單。

    所需檔案。 載入 completion.css、completion-motion.js 及主題樣式。

    先把結果放進 data-reveal-content，並為每個結果項目加上 data-reveal-row，再呼叫 play()。它只負責已準備內容的動畫。

        <label class="completion-item">
          <input type="checkbox" class="completion-checkbox" />
          <span class="completion-item-content">投保前要確認的問題</span>
        </label>
      </li>
    </ul>
  </div>
</div>
